
# 選課助手 CLASS 開發規格

## 1. 專案目標

用 Streamlit 製作中央大學課程資訊整合與比較工具，讓學生能在同一處搜尋課程、查看有來源的課程與教師資訊，並依自己的條件篩選和比較候選課程。

### 問題與使用者

- **初版使用情境：**中央大學學生挑課時，需要在選課系統多個頁面找課、查看學長姐修課評論，並另外搜尋教師評分方式或教學風格。
- **目前的訪談證據：**一位受訪者提到使用學校選課系統時會在多個頁面找課、查看以前修課者的評論，並用 Google 搜尋教師評分方式與教學風格；受訪者提到會考慮上課時間及是否必修。這是個人經驗，不代表所有學生。
- **既有系統能力：**中央大學選課系統已有衝堂辨識，因此本專題不把衝堂檢查或取代選課系統列為核心功能。
- **待驗證假設：**把分散的課程資料、評分資訊與修課心得集中整理，附上來源並提供並排比較，能減少逐頁搜尋的麻煩。後續需訪談其他學生並進行試用確認。
- 初版先服務「正在規劃課表、需要比較多門課的中央大學學生」，不宣稱已針對新生、外籍生、輔系生、雙主修生等每個族群驗證需求。

### 與直接使用 GPT 的差異

- 不是只提供聊天回答，而是先整理一份範圍明確、可搜尋的中大課程資料集，讓使用者可以用相同欄位搜尋、篩選和並排比較多門課。
- 將課程基本資料、評分方式、教師資訊及修課心得摘要集中呈現；每項資料都能追溯到來源，未知資訊標示「未提供」，不讓 AI 補猜。
- AI 僅協助根據已整理的資料摘要差異或說明符合條件的原因；核心價值是中大情境的結構化資料與比較流程，而不是一般用途的聊天功能。
- Demo 必須展示資料整合、來源標示和多門課比較；不可只展示一段 GPT 生成文字來代表產品價值。

## 2. MVP 功能表

| 功能 | 使用者做什麼 | 程式要做什麼 |
|---|---|---|
| 分頁導覽與首頁 | 從左側選單切換首頁、個人檔案、願望清單、AI 排課與課程搜尋 | 每項主要工作各自顯示，避免搜尋、排課和筆記介面擠在同一頁 |
| 個人檔案與選課願望清單 | 儲存系級、年級、修課狀況、學分與時間偏好；整理已確定課程 | 在本機保存個人選課設定、已確定課程，以及每門課的文字、照片和錄音筆記 |
| 週課表與行事曆匯出 | 查看週次和每天日期，調整課程顏色，下載課表照片 | 依使用者設定的學期第 1 週星期一顯示日期；匯出目前週次的 PNG 課表 |
| 搜尋與查看整合課程資訊 | 搜尋課名、教師或系所，查看課程介紹、必選修、時間、評分方式、教師資訊及修課心得 | 從 `courses.json` 讀取官方有限查詢結果，提供關鍵字搜尋與篩選，集中顯示資料和各自來源 |
| 依學生系級與興趣推薦 | 輸入系所、年級、學期、興趣和學分條件，選擇要比較的方案數 | 依 `curriculum.json` 中已核對的系級課程和官方通識分類，搭配本學期開課資料產生多套可替換的課表草案；缺少資料時清楚標示，不猜測必修或分類 |
| 分開瀏覽通識與系所課程 | 選擇全部課程、系所課程或通識課程，再依通識類型篩選 | 核心通識與一般通識在介面中分開標示；通識類型欄顯示官方分類，沒有已核實分類時標示「未分類」 |
| 依個人條件篩選與比較 | 選擇感興趣課程，指定必修狀態、學分、上課日或教師等比較條件，選取數門課並排查看 | 以一般 Python 規則篩選課程，並排顯示所選課程的共同欄位和差異；衝堂仍以選課系統確認 |
| AI 輔助比較摘要 | 對已選課程按下「整理差異」，查看摘要 | 將所選課程的已整理欄位與來源送至既有 AI 服務，生成簡短比較摘要；不新增資料、不代替使用者決定 |

Demo 可用 `scrape_demo.py` 對中央大學官方公開課程查詢頁進行有限查詢；預設抓取 1151 文學院 4 個大學部單位（中國文學系、英美語文學系、法國語文學系、文學院學士班）、理學院 5 個大學部單位（數學系、物理學系、化學學系、光電科學與工程學系、理學院學士班），以及核心通識課程和通識教育中心的一般通識課程；不抓取 1152。這些是開課單位範圍，不代表每筆開課都適用大學部或特定年級；年級仍以資料是否提供為準。系所課程、核心通識和一般通識在畫面分開顯示。通識類型（例如藝術、自然、數學、資訊）需依已核實的官方分類維護；未核實的課程標示「未分類」，不依課名猜類型。資料保留學期標記，介面不會混合比較。不登入、不大量爬取、不繞過存取限制，也不排程重複請求。輸出需記錄查詢來源與日期。課程評論和教師資訊仍須由小組整理並標明來源；示範評論不得假裝成真實學生評論。心得以小組撰寫的摘要為主，不大量複製原文；確認資料來源允許使用並保留出處，若使用條款不明則不納入該來源。AI 僅負責摘要比較，不訓練模型。

## 3. 技術與限制

- 使用 Python 與 Streamlit 製作網頁。
- 爬蟲結果放在專案內的 `courses.json`，用 Python 標準函式庫 `json` 讀取；不使用資料庫。`menu.json` 可保留作為示範資料。
- 只使用已學過的 Python 基礎：變數、`if`、`for`／`while` 迴圈、函式、`list`／`dict` 與檔案讀取。
- 使用 `streamlit`、`requests`、`Pillow`、Python 標準函式庫 `json`，以及一種小組選定的既有 AI 服務 API/SDK；不使用 pandas 或自行訓練模型。`Pillow` 用於產生可下載的 PNG 課表。
- AI API/SDK 是唯一外部服務例外，用於根據課程資料產生比較摘要或回應課表規劃對話。API 金鑰從 Streamlit secrets 讀取，不得寫入程式碼或提交到版本控制。
- 個人檔案、願望清單、課程筆記、照片和錄音只儲存在本機；課程筆記與附件不會傳送給 AI。
- 課程搜尋、條件篩選和欄位比較全部使用可解釋的 Python 規則；AI 不可新增課程或聲稱 JSON 沒有的課程／教師資訊。
- 第一週先確認 AI 服務可取得、金鑰可安全設定且 API 可呼叫。若無法取得服務，須清楚標示 AI 摘要不可用，但仍能搜尋、篩選和並排比較；不得把固定文字標稱為 AI 生成。
- GPT 可在開發準備階段協助把小組已取得的課程資料整理成 JSON 草稿；組員必須逐筆核對欄位和來源後才能使用。不得把 GPT 當成資料來源或未經核對的網頁爬蟲。
- 使用簡單、短小的函式；避免類別、遞迴、複雜演算法及尚未學過的語法。
- 所有自行撰寫的程式註解使用中文。程式中的錯誤需清楚顯示，不能在讀取資料失敗時假裝成功。
- 第一版只支援事先整理好的小型資料集或單一單位的官方公開查詢結果；不保證涵蓋所有中大課程或即時開課狀態。Demo 須標示資料來源與學期。
- Demo 使用標示清楚的示範資料，3 分鐘內展示：搜尋課程、查看資訊來源、篩選並排比較、查看 AI 比較摘要。

### AI 比較摘要規則

- 傳給 AI 的內容只包含產生摘要所需的所選課程欄位及來源；不傳送姓名、學號或其他個人資料。
- AI 摘要須以提供的資料為依據；資料不足時，明確說明無法比較，不推測教師風格或課程評價。
- 頁面標示摘要由 AI 產生，並同時顯示用到的課程資訊及來源。使用者須能回到原始資料自行判斷。
- API 呼叫失敗時顯示清楚訊息，保留搜尋、篩選和並排比較功能，不得把錯誤包裝成成功的 AI 結果。

## 4. 資料格式：`courses.json` 與 `menu.json`

檔案最外層是 JSON 陣列。`menu.json` 每筆資料代表一個課程的「一個開課班別」；爬蟲輸出的 `courses.json` 另含 `serial_number`、`semester`、`time` 原始節次字串。每筆爬取資料均保留官方頁面來源與查詢日期。`time` 保留官方原始節次與教室字串；`meeting_times` 依已確認的節次表增加鐘點欄位，無法辨識的節次不換算。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `offering_id` | 字串 | 開課班別識別碼；每筆資料唯一 |
| `course_id` | 字串 | 課程識別碼；同一課程的不同班別可使用相同識別碼 |
| `course_name` | 字串 | 課程名稱 |
| `department` | 字串 | 開課系所 |
| `target_year` | 字串 | 適用年級；不限定時填「不限」 |
| `section` | 字串 | 班別 |
| `credits` | 整數 | 學分數 |
| `is_required` | 布林值或 `null` | 官方資料確認時為必修／選修布林值；缺少欄位時為 `null` |
| `offering_type` | 字串 | 官方必選修原文整理成「必修」、「選修」或「未提供」 |
| `code_card_requirement` | 字串 | 密碼卡規定：`需要`、`可選`、`不需要` 或 `未提供` |
| `not_for_preliminary` | 布林值或 `null` | 官方標示不列入初選分發時為 `true`；沒有明確資料時為 `null` |
| `teacher` | 字串 | 授課教師 |
| `teacher_gmail` | 字串 | 教師公開且已核對的 Gmail；沒有可靠來源時填「未提供」，不得依姓名推測 |
| `meeting_times` | 陣列 | 上課時段；可辨識節次會保留 `periods`，並換算成星期、開始和結束時間；未辨識的節次只保留原碼 |
| `grading` | 字串 | 評分方式；未知時填「未提供」 |
| `teaching_style` | 字串 | 教學風格描述；未知時填「未提供」 |
| `reviews` | 字串陣列 | 修課心得摘要；無資料時使用空陣列 |
| `sources` | 物件陣列 | 資料來源清單；每個物件含 `name`、`url`、`fields`、`checked_at`，可含 `note` 備註，記錄來源名稱、連結、支持的欄位及查核日期 |

鐘點使用 24 小時制、補零格式的 `HH:MM`（例如 `09:00`），星期使用「一」到「日」。節次依使用者提供的中大時段換算：第 1 至 4 節分別從 08:00、09:00、10:00、11:00 開始；第 5 至 9 節分別從 13:00 至 17:00 開始；A、B、C 節分別從 18:00、19:00、20:00 開始。每節 50 分鐘，節間 10 分鐘；跨午休的節次會分開呈現。未辨識節次保留代碼，不推測鐘點。

```json
[
  {
    "offering_id": "DEMO101-A",
    "course_id": "DEMO101",
    "course_name": "Python 資料整理（示範課程）",
    "department": "示範系所",
    "target_year": "不限",
    "section": "A",
    "credits": 2,
    "is_required": false,
    "code_card_requirement": "未提供",
    "not_for_preliminary": null,
    "teacher": "示範教師",
    "teacher_gmail": "未提供",
    "meeting_times": [
      {
        "day": "一",
        "start": "09:00",
        "end": "10:50"
      }
    ],
    "grading": "示範：作業 60%、期末專題 40%",
    "teaching_style": "示範資料，非真實教師資訊",
    "reviews": [
      "示範評論，非真實學生心得"
    ],
    "sources": [
      {
        "name": "小組自製示範資料",
        "url": "",
        "fields": ["course_name", "credits", "teacher", "grading", "teaching_style", "reviews"],
        "checked_at": "2026-11-24",
        "note": "虛構示範資料，非真實課程或學生評論"
      }
    ]
  }
]
```

官方課程列表的備註若標示 `Code Card:Required` 或 `Not for preliminary`，介面需在課程選項、詳情與比較畫面清楚顯示。教師 Gmail 只有在官方公開或由小組核實並附上來源時才顯示；否則顯示「未提供」。

## 5. 檔案結構

```text
course-helper/
├── app.py              # Streamlit 介面與主要流程
├── calendar_export.py  # 學期週次日期、課程顏色與 PNG 課表輸出
├── pages/              # 個人檔案、願望清單、AI 排課與課程搜尋頁面
│   ├── AI_幫忙排課.py
│   ├── 個人檔案.py
│   ├── 選課願望清單.py
│   └── 課程搜尋與比較.py
├── course_workspace.py # 本機個人設定、願望清單、附件與第 1 週日期儲存
├── scrape_demo.py      # 單學期、單一開課單位的公開課程查詢
├── courses.json        # 爬蟲產生的官方查詢資料
├── curriculum.json     # 小組人工核對的系級課程地圖與通識分類
├── menu.json           # 小組整理的課程示範資料
├── requirements.txt    # 專案依賴，包含 Streamlit、Pillow 與選定的 AI SDK
├── .gitignore          # 忽略金鑰等本機設定
└── spec.md             # 本開發規格
```

API 金鑰以本機 `.streamlit/secrets.toml` 設定，不提交該檔案或任何金鑰。個人檔案 `course_profile.json`、願望清單與筆記 `course_workspace.json`、媒體資料夾 `course_workspace_media/` 也由 `.gitignore` 排除。

## 6. 函式清單

組員以「組員 1–3」暫稱，實際開始工作時由小組自行對應姓名。函式名稱採英文，介面文字與程式註解使用中文。

| 函式名稱 | 輸入 | 輸出 | 負責組員 |
|---|---|---|---|
| `load_menu` | JSON 檔案路徑 | 課程班別的 `list`；讀檔或 JSON 格式錯誤時回報錯誤 | 組員 1 |
| `search_courses` | 課程班別清單、關鍵字 | 符合課名或教師姓名的課程班別清單 | 組員 1 |
| `filter_courses` | 課程班別清單、使用者選取的篩選條件 | 符合條件的課程清單 | 組員 2 |
| `compare_courses` | 課程清單、使用者選取的開課班別 ID | 供介面並排顯示的課程欄位資料 | 組員 2 |
| `summarize_comparison` | 已選課程欄位資料及來源 | AI 產生的簡短比較摘要；API 失敗時回報錯誤 | 組員 3 |
| `main` | 無；載入課程、個人檔案與願望清單摘要 | 顯示首頁與各功能頁面的導覽入口 | 組員 3 |
| `course_search_page` | 無；從 `courses.json` 載入資料並讀取 Streamlit 輸入 | 顯示搜尋、篩選、課程詳情、並排比較與 AI 摘要 | 組員 3 |

### 函式行為補充

- `search_courses` 的關鍵字空白時，回傳全部課程班別。
- `filter_courses` 只按使用者明確選取的條件篩選，不把未提供的資料視為符合或不符合。
- `compare_courses` 依唯一的 `offering_id` 取回所選資料；欄位缺漏時顯示「未提供」，並保留各欄位來源資訊。
- 一般選課系統已提供的衝堂辨識不在本專題重做；課程時間只作為搜尋、篩選及比較資訊呈現。
- 並排比較至少顯示課名、教師、必選修、學分、上課時間、評分方式、教學風格、修課心得和資料來源。
- `summarize_comparison` 僅可摘要已選課程 JSON 中的資訊；API 失敗時仍可使用其餘功能，並明確顯示摘要未產生。
- 小組需先界定資料範圍，從可查核來源整理小型資料集；爬蟲只執行單一學期、單一開課單位的公開查詢，不要求涵蓋全校課程，也不做大量自動爬取。
- GPT 可協助把已取得的來源資料轉成 JSON 草稿，但組員須逐筆核對內容與來源；未核實的內容不得放入正式資料集。

## 7. 驗收條件

- 搜尋空白關鍵字會顯示全部課程；輸入課名或教師關鍵字會顯示符合的課程。
- 使用者可用至少兩項條件篩選課程，並選取多門課並排比較。
- 課程詳情及比較畫面能顯示課程名稱、教師、必選修標記、學分、時間、評分方式、教學風格、心得和來源；缺少資料時顯示「未提供」，不自行補寫。
- 每筆非虛構資料都能找到其來源；示範資料明確標示為虛構，不偽裝成真實課程或學生評論。
- AI 比較摘要只使用已選課程 JSON 資料；API 失敗時仍可搜尋、篩選及比較，頁面清楚指出 AI 摘要未產生。
- Demo 能清楚展示：相較直接使用 GPT，本工具將已整理的中大課程欄位集中於一處、可篩選並排比較，且提供可追溯來源。
- 不展示或宣稱未驗證的使用者人數、節省時間或滿意度。

## 8. 四週工作安排與成果驗證

| 週次 | 工作與檢查點 |
|---|---|
| 第 1 週 | 透過訪談確認最重要的課程資訊需求；選定可合法使用的資料來源與有限資料範圍；確認 AI API/SDK 和金鑰設定可行。GPT 可協助將已取得資料整理成草稿，組員核對來源與正確性 |
| 第 2 週 | 完成 JSON 讀取、搜尋、課程詳情和篩選介面；整理並驗證小型資料集 |
| 第 3 週 | 完成多課程並排比較、AI 摘要和來源呈現；測試欄位缺漏、AI 資料不足及 API 失敗情況 |
| 第 4 週 | 依驗收條件測試、修正錯誤、試跑 3 分鐘 Demo；向同學試用並記錄實際觀察和回饋，不預先填寫成效數字 |

### Demo 流程

在 3 分鐘內展示：搜尋課程 → 查看整合的課程、教師與修課資訊及來源 → 依條件篩選並排比較數門課 → 查看 AI 根據資料產生的比較摘要。Demo 說明現有選課系統已能辨識衝堂，因此本工具聚焦在選課前的資料整理與比較，而非重做既有功能。若當下 AI 服務無法使用，需明確說明並展示並排比較，不冒稱為 AI 結果。

## 9. AI 課表規劃對話

- AI 課表規劃有獨立頁面，透過左側頁面選單進入；首頁、個人檔案、選課願望清單與課程搜尋也各自分頁。
- 使用者可在畫面輸入系所、年級、系級必修、已修課程、想修學分、學分上限、不可上課時間、偏好上課日、課業負荷與自然語言需求。
- 偏好上課日可直接在週課表的星期欄點選；偏好時段可點選一小時格子並以顏色標記。推薦方案會優先排列符合偏好的課程，不會把偏好當作硬性限制。
- AI 必須詢問或指出資訊不足之處，不得以猜測補足系級規定、畢業門檻或實際開課資訊。
- 課表草案只能引用 `courses.json` 中既有的 `offering_id`、課名、教師、學分、時間及來源。
- 草案只供規劃參考；畫面必須提醒使用者回選課系統確認衝堂、實際開課與選課資格。
- AI 對話之外，推薦區也會依 `curriculum.json`、興趣關鍵字及學分條件產生可替換的多套方案；此規則推薦不會把未核對的課程標成系級必修。
- 已確定課程顯示在 AI 排課頁的左側工作欄；每門課提供文字筆記、拍照、照片上傳與錄音功能。筆記和附件只保存在本機，不會傳送給 AI。

### `curriculum.json` 格式

最外層是 JSON 物件，包含 `department_curricula` 和 `general_education_categories` 兩個陣列。每筆系級資料需提供 `department`、`grade`、`semester`、`required_course_ids`、`elective_course_ids` 和可追溯的 `sources`；課程識別碼必須能對應本學期開課資料。通識分類需提供官方類別名稱、對應的 `course_ids` 及來源。未有官方分類資料時維持空陣列，介面顯示「未分類」。

```json
{
  "department_curricula": [
    {
      "department": "資工系",
      "grade": "大二",
      "semester": "1151",
      "required_course_ids": ["CS1001"],
      "elective_course_ids": ["CS2001"],
      "sources": [
        {
          "name": "系所官方課程地圖",
          "url": "https://example.edu/curriculum",
          "checked_at": "2026-11-26"
        }
      ]
    }
  ],
  "general_education_categories": [
    {
      "name": "官方分類名稱",
      "course_ids": ["CC0109-*"],
      "sources": [
        {
          "name": "官方通識分類頁",
          "url": "https://example.edu/general-education",
          "checked_at": "2026-11-26"
        }
      ]
    }
  ]
}
```

範例網址與課號僅示意格式，不代表已驗證的課程資料。正式資料須由小組逐筆核對來源。

## 10. 週課表與成績

- 使用者可選課程班別，依 `meeting_times` 直接產生一週課表。
- 未手動選擇課程時，按下「直接產生課表」會依所選系所、年級、興趣、學分和偏好產生推薦草案；缺少可確認的鐘點時顯示課程清單與提醒，不虛構時間或寫入週曆。
- 年級可從大一至大四的下拉選單選擇；直接產生課表前可依系所、適用年級和班別篩選。課程未提供適用年級時仍保留在結果中並顯示提醒；班別可留空，表示包含所有班別或未分班課程。
- 週課表以每小時一列呈現；每堂中大課程按 50 分鐘上課、10 分鐘下課顯示。已確認的節次依中大時段對照換算；無法辨識的代碼保留原文並提醒使用者確認。
- 課表以星期一至星期日呈現，使用者可編輯課堂名稱、星期、開始與結束時間、教師或備註、待辦事項，也可刪除課堂或加入自訂活動。
- 行事曆可設定每學期第 1 週的星期一，依週次顯示日期；初始日期只是依學期月份估算，使用者必須依中央大學官方校曆核對後儲存。使用者可修改課堂顏色，並將目前選取的週次匯出、下載為 PNG 照片。
- 選取的偏好上課日會標記在星期欄標題，偏好時段會以顏色標記在對應格子；資料有可確認的鐘點時，偏好時段會提供給課表推薦排序使用。
- 多套推薦方案依已核對的系級課程、課程興趣和學分條件產生，使用者可在每套方案中替換推薦課程；資料不足時要指出未包含的必修或分類，不能假稱方案符合畢業規定。
- 使用者可為課堂記錄成績項目、得分與權重；程式依已記錄資料計算加權期末成績。
- 權重合計超過 100% 時須警告使用者；資料不足或尚未輸入全部成績項目時，不宣稱為正式期末成績。
- 已確定課程與文字、照片、錄音筆記會保存在本機 JSON 與媒體資料夾，不會傳送給 AI，也不納入版本控制。
